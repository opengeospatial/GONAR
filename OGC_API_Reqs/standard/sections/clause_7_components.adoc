[[components]]
== COMPONENTS

=== Overview

This clause specifies the requirements classes that define the components to be used to define a Need.

A Need is a specific case of a Record and, therefore, complies with the relevant requirement classes of the https://docs.ogc.org/is/20-004r1/20-004r1.html[OGC API – Records], taking into account the particular characteristics of the elements described in this section.

In this section, only the elements that differentiate the OGC API – Requirements from the https://docs.ogc.org/is/20-004r1/20-004r1.html[OGC API – Records] are described.

[[need-item]]
=== Requirements Class "Need" (Component)

==== Overview

include::../requirements/requirements_class_need_item.adoc[]

The Need requirements class defines how the GONAR data model is combined with the Record data model described in section 7.2 of https://docs.ogc.org/is/20-004r1/20-004r1.html[OGC API – Records]. The Need requirements Class defines the requirements for a _Need Item_. 
This requirements class follows the instructions described in recommendation /rec/record-core/extensions in section 7.2.3 of https://docs.ogc.org/is/20-004r1/20-004r1.html[OGC API – Records].

Although this Standard does not mandate any particular encoding for a Need Item, a JSON encoding is proposed. Other encodings are allowed but are not described in this Standard.

[[need_item_props]]
==== Properties
The properties of a record that contains a `need` use the GONAR data model for the Need Item as described in section $$$7.2$$$ of OGC GONAR Standard: Data Model. The table <<tbl_record_need_item>> maps GONAR need properties with the properties defined in OGC API - Records section 7.2 in table 8 and table 9.

[#tbl_record_need_item,reftext='{table-caption} {counter:table-num}']
.Record properties mapped to need data model
[cols="25,45,35",options="header"]
|===
|Property in records|Obligation |Description |Property in need data model
|id |**required** |A unique record identifier assigned by the server |Id
|title |**required** |A human-readable name given to the resource described by this record. |Description
|geometry |optional |A spatial extent associated with the need described by this record. Can be null if there is no associated spatial extent |SubArea transformed to a geometry
|time |optional |A temporal extent associated with the need described by this record. Can be null if there is no associated temporal extent.	time |TemporalExtent
|conformsTo |optional |The extensions/conformance classes used by this record |"https://www.opengis.net/spec/ogcapi-requirements-1/1.0/conf/needs"
|externalIds |optional | One or more identifiers, assigned by an external products or to ISO 19113 product specifications, related to the need described by this record (if they already exist) | RelatedProductDescription as URL to the related product
|links |**required** (link to data requirement) |A list of links to data requirements and projects related to this record. |DataRequirement (rel=related) and Project (rel=related)
|===

The <<tbl_need_item>> provides an informative list of need properties that could not be mapped to the original record model and constitute and extension of the original record properties.

.Need Item extension
[cols="20,20,40",options="header"]
|===
|Property |Obligation | Description

|area |optional | Geographic scope or scale of the Need (see possible values in the GONAR data model)
|subarea |optional| Name of the specific geographical area, region, locality, or any topographical feature name related to the Need. The property `geometry` contains coordinates representing the subarea.
|processToRealize |optional | Process or set of tasks that are necessary to realize the Need.
|relatedProductDescription|optional | Description of a product to be created or the outcome to be achieved by using in-situ data as a result of the process. `externalIds` may be used to document identifiers (if they already exist).
|===

==== Overview

include::../requirements/requirements_class_needs_collection.adoc[]

==== Requirements Class "GeoJSON" (Component)
https://datatracker.ietf.org/doc/html/rfc7946[GeoJSON] is a commonly used format based on JSON that is simple to understand and well supported by tools and software libraries. Since most Web developers are comfortable with using a JSON-based format, supporting GeoJSON is recommended. 

The following requirements apply when:

. The API endpoint advertises conformance to the JSON Conformance Class.
. The client negotiates that the content of the server's response be https://datatracker.ietf.org/doc/html/rfc7946[GeoJSON].
